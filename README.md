# 海龟汤 🐢

一个干净素雅、浅绿色风格的海龟汤（推理文字游戏）网站。支持用户注册登录、海龟汤库浏览预览、自己写故事与上传 txt 文件两种方式添加海龟汤。**数据存储在 MySQL 数据库，所有登录用户共享同一份海龟汤库。**

## 功能特性

- 🔐 **登录 / 注册**：进入网站先登录，用户名与密码匹配才能进入；未登录会被拦截，可随时注册新账号
- 📚 **海龟汤库（全局共享）**：所有用户看到同一份全量海龟汤，按添加时间从上到下列表展示，每条含「汤名 / 类型（清汤·红汤）/ 风格（本格·变格）/ 难度（最高五颗星）」，行尾「预览」按钮弹出小窗查看汤面（可滚动）与汤底
- ✍️ **添加海龟汤**：分「自己写故事」与「上传故事」两类
  - 自己写故事：左侧占 1/5 屏幕圆角方框（红光闪烁）填汤面，右侧占 1/5 屏幕圆角方框（紫光闪烁）填汤底
  - 上传故事：页面正下方「上传文件」按钮，上传 .txt 文件自动解析汤名/汤面/汤底
- 🗑️ **删除权限**：只能删除自己添加的海龟汤（记录创建者）
- 🛡️ **管理者入口**：侧边栏底部的独立入口，需口令验证（口令取自环境变量 `ADMIN_PASSWORD`）。用于上传海龟汤**知识库**文件（汤面 / 汤底 / 推理逻辑），作为判题参考注入 AI 陪玩的提示词，**全站用户共享**
- 🖱️ **小海龟光标**：鼠标悬停交互元素时，光标变成一只绿色小海龟
- 🌿 **流式布局**：浅绿色自然素雅风格，多页面 + 左侧侧边导航栏

## 技术栈

- **后端**：Node.js 原生 `http` 模块 + `mysql2`；自实现 JWT 鉴权（HS256）
- **数据库**：MySQL（自动建库建表）
- **前端**：原生 HTML / CSS / JavaScript，无框架、无构建
- **存储**：用户与海龟汤数据存 MySQL；上传的原始 txt 文件存 `data/uploads/`

## 本地运行

### 1. 准备 MySQL

确保本机 MySQL 已启动（Windows 服务名如 `MySQL95`），并确认 root 账号密码。

### 2. 配置数据库连接

复制 `.env.example` 为 `.env`，填写你的数据库信息：

```bash
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的密码
DB_NAME=haiguitang
PORT=3000
JWT_SECRET=改成随机字符串
ADMIN_PASSWORD=管理者入口口令（用不到管理者入口可留空）
```

> 数据库 `haiguitang` 不存在也没关系，服务启动时会**自动创建**数据库和表。

### 3. 安装依赖并启动

```bash
npm install
node server.js
```

浏览器打开 <http://localhost:3000>。

## 数据模型

### users 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(36) | 主键（UUID） |
| username | VARCHAR(50) | 用户名（唯一） |
| salt | VARCHAR(32) | 密码盐 |
| password_hash | VARCHAR(64) | 加盐 SHA256 哈希 |
| created_at | DATETIME | 注册时间 |

### soups 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(36) | 主键（UUID） |
| title | VARCHAR(200) | 汤名 |
| face | TEXT | 汤面（谜面） |
| bottom | TEXT | 汤底（答案） |
| type | VARCHAR(10) | 清汤 / 红汤 |
| style | VARCHAR(10) | 本格 / 变格 |
| difficulty | TINYINT | 难度 1~5 星 |
| author_id | VARCHAR(36) | 创建者 id |
| author_name | VARCHAR(50) | 创建者用户名 |
| created_at | DATETIME | 创建时间 |

### kb_documents 表（管理者知识库上传台账）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(36) | 主键（UUID），同时作为向量库里的 `docId` |
| filename | VARCHAR(255) | 上传的文件名（已净化，不含路径） |
| md5 | CHAR(32) | 内容指纹，**唯一键**，用于重复上传去重 |
| blocks | INT | 解析出的知识单元（一道汤 = 一个单元） |
| chunks | INT | 实际写入向量库的条数 |
| chars | INT | 原始字符数 |
| encoding | VARCHAR(30) | 识别出的编码（utf-8 / gbk 等） |
| operator_id / operator_name | VARCHAR | 上传者 |
| created_at | DATETIME | 上传时间 |

> 向量本体不在这张表里，而是落在 `data/chroma/haigui_kb.json`（与题库向量 `haigui_soups` 分属不同
> collection，可独立删除/清空）。本表只存可查询的元数据。

## 管理者入口与知识库（RAG）

### 1. 配置口令

代码里**不写任何默认口令**（仓库是公开的，写进源码等于对外公开）。配置方式：

```bash
# 本地：把它加进 .env
ADMIN_PASSWORD=你的管理者口令

# 服务器：写进 .env 后重启进程
pm2 restart haigui
```

未配置时，管理者入口会返回「未启用」提示，**其余功能完全不受影响**。

### 2. 使用

登录后点击侧边栏**最底部**的「管理者入口」→ 输入口令 → 进入管理页。页面提供：

| 功能 | 说明 |
|---|---|
| 知识库概览 | 已上传文件数 / 知识单元数 / 向量条数 / 累计语料量 |
| 批量上传 | 拖拽或点选多个 `.txt`，单次最多 50 个、单个 ≤8MB、单次总量 ≤50MB |
| 已入库文件 | 列表 + 分页 + 按文件删除（连同向量一起删） |
| 检索测试 | 输入一句玩家提问，查看真实召回内容与相似度分数，用于校准门槛 |
| 清空知识库 | 需要输入确认文本的两步确认 |

### 3. 支持的 txt 格式

解析器按「一题一块」切分，优先识别字段标签，同时兼容无标签的经典三段式：

```
汤名：雪夜里的脚印                 ← 也可省略，首行短文本自动作为汤名
汤面：一个人在雪地里留下两排脚印，却没有往回走的痕迹。
汤底：他是被雪橇拉走的，回来的是雪橇，不是他的脚。
推理逻辑：关键在只有两排脚印，说明他离开时不是走回来的。
```

- 字段标签支持：`汤名/标题`、`汤面/谜面/题干/故事`、`汤底/答案/谜底/真相`、`推理逻辑/推理过程/解析/思路`
- 一题一块；多题可用 `====`、`----` 等分隔线隔开，也可用 `1.`、`【1】`、`第1题` 作为题目起始
- 标签**单独成行**也支持（`汤底` 一行，下一行开始写内容）
- 完全解析不出结构的散文本会回落到 1000 字 / 100 字重叠的定长切分
- 编码：UTF-8、UTF-8 BOM、**GBK（Windows 记事本「ANSI」）** 都会自动识别

### 4. 工作原理

```
管理页上传 txt
     │
     ▼
编码识别（UTF-8 / GBK）
     │
     ▼
结构化切分：一道汤 = 一个检索单元（面 + 底 + 推理逻辑）
     │
     ▼
MD5 去重（kb_documents.md5 唯一键；重复内容直接跳过）
     │
     ▼
向量化（1024 维 n-gram 哈希）→ 写入 collection haigui_kb
     │
     ▼            ┌──────────────────────────────────────────┐
     │            │ 玩家在 AI 陪玩中提问（任何用户、任何汤） │
     │            └───────────────────┬──────────────────────┘
     │                                ▼
     │                    用提问做向量检索 Top-K（默认 4 条，分数门槛 0.08）
     │                                ▼
     └───────────────► 注入汤主的 system prompt（标注为内部判题参考、禁止向玩家泄露）
                                      ▼
                          用户自己配置的大模型据此判题
```

**为什么需求「其他用户调用各自 API 时也能用上知识库」不需要用户做任何事**：
检索与提示词组装全部发生在**服务端**。用户在自己的「个人设置」里填的只是
`API Base URL / Key / 模型名`，服务端拿这些配置去调他们的大模型时，
system prompt 里已经带上了知识库召回内容。因此知识库对所有用户、所有大模型自动生效。

**注意**：知识库只增强**大模型引擎**。内置离线引擎（未配置大模型的用户）保持原有行为不变
—— 它刻意只做字面 bigram 匹配，不做模糊推断，这是产品取舍，不是缺陷。

### 5. 检索门槛怎么调

`knowledge-base.js` 顶部的 `DEFAULT_MIN_SCORE`（当前 `0.08`）与 `DEFAULT_TOP_K`（当前 `4`）。
本地 n-gram 向量是**字面匹配**而非语义匹配，且知识库单个单元比题库切片长（会被稀释），
所以分数整体偏低是正常的。管理页的「检索测试」会显示真实分数与是否过门槛，
按自己语料的分数分布调整即可。

> 想升级成语义检索：只需替换 `vector-store.js` 里 `embed()` 的实现
> （换成任意 embedding API，如 DashScope `text-embedding-v2`），
> collection 与检索逻辑都不需要改。

## 安全说明

- 密码使用「加盐 SHA256」哈希存储，不保存明文
- 登录鉴权使用自实现 JWT（HS256），默认 7 天过期
- 管理者口令只从环境变量 `ADMIN_PASSWORD` 读取，**代码内无任何默认值**
- 管理者令牌与登录令牌共用同一套 HMAC 签名，但要求 payload 带 `role=admin`；
  普通用户的令牌无法访问管理接口（已验证越权返回 403）
- 管理令牌有效期 2 小时，前端存在 `sessionStorage`（关闭标签页即失效）
- 同一 IP 连续输错口令 5 次锁定 15 分钟
- 所有 SQL 使用**参数化查询**（`?` 占位符），防 SQL 注入
- 上传文件名只作元数据，永不参与磁盘路径拼接；原始文件一律用 UUID 命名
- 生产环境务必设置 `JWT_SECRET` 为随机长密钥
- 数据库密码通过环境变量 / `.env` 注入，不硬编码在代码中

## 上传文件格式约定

上传的 .txt 文件建议按以下格式：

```
汤名（第一行，≤30 字会被识别为标题）
汤面内容……
汤底
汤底内容……
```

分隔符支持「汤底」「答案」「谜底」「====」「----」等，也可不写标题（系统会提示手动补充）。

**编码**：自动识别 UTF-8、UTF-8（含 BOM）与 **GBK**。Windows 记事本「另存为 → ANSI」保存的 txt
实际是 GBK，早期版本按 UTF-8 硬解会得到整篇乱码，现已修正（识别结果会在接口返回的
`encoding` 字段里标出）。

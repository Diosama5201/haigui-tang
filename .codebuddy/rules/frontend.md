# 前端编码规范（public/）

## 导航 —— 最容易踩的坑

- **所有内部跳转必须调用 `goto(hash)`**，禁止直接写 `location.hash = '#/xxx'`
- 原因：给 `location.hash` 赋**相同值**时浏览器不触发 `hashchange`，页面不会重渲染。
  真实事故：用户从"继续游玩"进入时 hash 已经是 `#/ai/play`，点按钮后界面毫无反应，
  表现为"按钮卡在保存中"。
- 新增按钮/链接时，只要目标是站内路由，一律走 `goto()`

## 结构划分

- 页面外壳：`app.html`（主应用）、`index.html`（登录）
- 视图与交互：全部在 `js/app.js`
- 接口调用：**新增接口一律写进 `js/api.js`**，不要在 `app.js` 里直接 `fetch`
- 样式：全部集中在 `css/style.css`

## 主题

- 亮/暗切换通过根元素 `data-theme` 属性实现，状态存 `localStorage`（键名 `ht_theme`）
- 新增颜色一律走 CSS 变量，**禁止写死色值**——写死会导致暗色模式下文字不可读
- 亮色为默认；图表/进度条等有语义的颜色也要在暗色下有对应变量

## 无构建约束

- 不使用打包器，`<script type="module">` 直接加载，改完刷新浏览器即生效
- **不要引入任何 npm 前端依赖**，需要能力就用原生 API 自己写
- 新增 JS 文件记得在 `app.html` 中按依赖顺序引入

## 状态与网络

- 进度条、引擎标识等 UI 状态由接口返回值驱动，**不要在本地另算一套**（会出现前后端不一致）
- 进度值只增不减（单调），避免界面来回跳
- 所有 `fetch` 都要处理失败分支并给出可读提示，不要静默失败

执行一次完整部署。**按下面的顺序做，不要跳步，也不要顺手改成别的方式。**

1. 检查待部署内容：运行 `git status` 和 `git diff --stat`，确认改动符合预期。
   如果存在未提交的改动，先向用户确认是否要包含进本次部署。

2. 判定影响面：对照 `.codebuddy/rules/deploy.md` 的「改动影响面」表格，判断本次是否需要
   重新上传后端、重新上传前端、或重装依赖。如果只改了前端，不要顺带重启后端。

3. 部署前告知用户当前提交号（`git log -1 --oneline`），便于出问题时回滚。

4. 执行部署：请用户在本机双击运行 `一键更新.bat`；只有在用户明确同意后，才可以代跑等价的
   scp / ssh 命令。
   **绝对不能把 `deploy.local.bat` 里的服务器地址、IP、密钥路径打印到对话里或写进日志。**

5. 部署后验证：请求 `/healthz` 应返回正常，再抽查一个页面能否打开。若失败，
   提示用户到服务器执行 `pm2 logs haigui` 查看原因。

6. 汇总结论：部署了哪些文件、当前提交号、验证结果、以及出问题时的回滚命令。

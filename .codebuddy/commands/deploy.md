执行一次完整部署。**按下面的顺序做，不要跳步，也不要顺手改成别的方式。**

1. 检查待部署内容：运行 `git status` 和 `git diff --stat`，确认改动符合预期。
   如果存在未提交的改动，先向用户确认是否要包含进本次部署。

2. 判定影响面：对照 `.codebuddy/rules/deploy.md` 的「改动影响面」表格，判断本次是否需要
   重新上传后端、重新上传前端、或重装依赖。如果只改了前端，不要顺带重启后端。

   **新增后端模块的硬性检查（2026-09-28 事故复盘）**：`一键更新.bat` 用 glob 上传**项目根目录**的
   全部 `.js` / `.json`。所以凡是被 `server.js` `require('./xxx')` 的模块**必须放在项目根目录**；
   一旦放进子目录，部署后 `server.js` 会在启动时抛 `MODULE_NOT_FOUND`，pm2 无限重启、
   3000 端口无监听、**整站拒连**。部署前先跑一遍：
   `grep -n "require('\./" server.js` 核对每个相对路径模块都在根目录。

3. 部署前告知用户当前提交号（`git log -1 --oneline`），便于出问题时回滚。

4. 执行部署：请用户在本机双击运行 `一键更新.bat`；只有在用户明确同意后，才可以代跑等价的
   scp / ssh 命令。
   **绝对不能把 `deploy.local.bat` 里的服务器地址、IP、密钥路径打印到对话里或写进日志。**

5. 部署后验证：**两件事都要做，缺一不可**——
   - `/healthz` 返回 `"status":"ok"` 且 `"db":"ok"`
   - 服务器上 `pm2 list` 的 `haigui` 状态是 **`online`**，且 `↺` 重启计数**没有持续增长**
     （跑两次 `pm2 list` 对比）。只要出现 `errored` 或计数在涨，就是崩溃重启，
     **不要**只看 `/healthz` 就宣布成功。
   若失败，到服务器执行 `pm2 logs haigui --lines 50 --nostream` 查看原因，
   必要时用 `C:\haigui\_bak\server.js.bak` 回滚。

6. 汇总结论：部署了哪些文件、当前提交号、验证结果、以及出问题时的回滚命令。
